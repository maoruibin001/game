# 从玩家的判断找体验问题

先选一个可观察的问题。例如玩家看到结果后会选什么、为什么选、能否看出世界发生了什么变化。把“好玩”“惊艳”留给有体验的人判断，留下能支持或推翻解释的现场。

## 先记录玩家怎么想

- 记录试玩包或入口、设备和起始存档。评“改好了吗”时，先确认地址实际提供的版本。复用可追溯的旧包或旧记录，按影响范围安排复测。
- 做首玩时先从正常入口开始，用新档，只读游戏里自然遇到的提示。停在第一次犹豫、意外反馈或想退出的地方，记下“我看到什么 → 我以为会发生什么 → 我做了什么 → 实际发生什么”，配时间或原画面。先保存这份记录，再看策划案、代码和旧结论。熟悉答案的人可做定向复测，明确标记身份。
- 已有玩家反馈时优先沿他的走法重现。若他以为某件事做不了，先留下使他作此判断的界面，再试该动作究竟能否执行。记录提示是在行动前、行动后还是藏在另一个面板里。

## 一次只改变一个能解释问题的条件

按现象选有区分力的对照。已经能回答问题的分支即可收手。

| 玩家现场 | 最有信息量的对照 | 实际看什么 |
| --- | --- | --- |
| 结果不完美就不敢提交 | 合格范例与合理偏差各走一次；再交换两张都成立、但表达不同的作品 | 提交是否可点、预选了什么、玩家能否改选，回应是否承认他实际交出的内容 |
| 同一决定有时让人迷路 | 从两个自然入口做同一动作，如步行与取景、地图与手记；操作后继续正常迈一步 | 人物处于哪种模式，地图是否可见，目的地和目标栏是否一致，下一次按键究竟做了什么 |
| 交付后以为故事结束或卡住 | 比较先交可选目标、先走主线两种合法顺序；关闭结果页，再看场景 | 下一目标、人物回话和世界变化能否接上同一件未完的事 |
| 主体已在画面或特效已触发，玩家没注意 | 用玩家正常机位与原图尺寸对照；短时变化保留前后几秒。先看无标注画面，再局部放大定位 | 让观察者先说第一眼看见什么、谁回应了谁；分别记录事件是否发生、是否被看见、是否被理解 |
| 玩家觉得自己的做法合理却判错 | 准备符合题意的另一角度、只缺一个要素的近似解、同地点背对主体等反例 | 合理变体能否通过，近似解是否收到具体提示，错误答案是否被误收 |

## 找到最小修正并证明它有用

根据现场区分机制缺失、已有能力难以发现、跨界面状态不一致、视觉反馈难以察觉。查对应实现和原回归走法，看看旧测试在哪一步替玩家作了决定。若证据不足，保留竞争解释，写出能区分两者的下一次操作。

按当前分工处理。评审角色向开发交付复现和验收条件；有实施授权时，保留原本成立的玩法与玩家选择，先改造成误解的那一步。改后用相同起点、输入和观察方式重跑原失败路线，再跑一个应继续成立的对照。必要时将这个分歧点加入现有行为回归，断言应落到玩家看得到的下一步。存档注入、时间步进和直接调用规则函数的结果可用于定位，单列其证明范围。

交付时用一段话写清 **玩家原先怎么理解、哪一处造成落差、改了什么、同条件重试得到什么、还有什么待验证**。附候选与原始证据。机器复验可证明界面状态和因果分支，真人首玩、审美与听感分别签收。初见记录封存后，如需本游戏的实例，可读[《拍一卷山色》复盘](references/mountain-roll.md)。
