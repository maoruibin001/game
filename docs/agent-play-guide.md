# 《拍一卷山色》Agent 试玩指南

## 选择入口

- **只有试玩地址**。用可操作真实桌面浏览器的工具打开作者提供的地址。内网试玩需要能访问相应网络。浏览器须能渲染 3D 画布。能点击按钮、截图、持续按键和拖动鼠标，就能像玩家一样试玩，无需克隆仓库、装依赖或启动服务。
- **拿到了本地预览地址**。直接使用作者给的当前地址。本地地址要求预览服务在浏览器可访问的机器上运行。若已在运行，复用原入口。
- **只有网页抓取或 DOM 阅读能力**。可以读标题和按钮，无法凭文本判断空间、构图或是否移动。请使用具备截图与真实键鼠控制的浏览器工具。只测到状态码或主菜单时，分别记录「资源可达」或「菜单可用」。

用桌面 Chrome 和独立试玩档案，开始前确认页面在前台。打开后等标题菜单里的「背上行囊，出发」可点，再开始输入。新档用独立浏览器档案，续玩选「接着上一次的路」。进度和相片跟随浏览器档案及访问地址，换域名、端口或浏览器档案会看到另一份存档。已有玩家存档时，别替对方点「重新出发」。

## 键鼠

| 动作 | 输入 |
| --- | --- |
| 行走与转身 | 按住 W、A、S、D；小步移动后先松键，再看当前画面 |
| 转视角 | 按住鼠标右键拖动，或按左右方向键；步行时也可用左键拖动 |
| 跑与跳 | 解锁后用 Shift 跑，步行时用空格跳 |
| 举机与收机 | C 或 Q |
| 举机取景 | 右键拖动或左右方向键转镜，A / D 可横移；相机面板可选焦段、画幅、定时等 |
| 拍照 | 举机后按空格或 F，或点屏幕快门按钮 |
| 交谈、取物与交件 | 靠近对象，看到对应提示后按 E |
| 看信、底片和相册 | J 打开旅行册 |
| 看路 | M 打开地图，找「景点导航」，选目的地后沿亮线走 |
| 返回或暂停 | Esc；卡进地形时可通过 HUD 或暂停菜单选「回到最近小路」 |

三维场景内优先用截图定位地标，再给画布发送真实键鼠输入。移动用按下、短暂保持、释放的完整操作，只发一个极短的按键事件可能走不出可见距离。每小段之后截图或看地图修正方向，换焦点、开面板或失误时先松开按键。

## 第一次试玩走这条线

1. **出发并认路**。新档点「背上行囊，出发」。等邮局和人物出现，量一次从打开网页到菜单可操作的时间。短按住 W 或 A，确认人物移动，再用 J 读阿禾的「能不能寄我一座山？」。
2. **拍一张自己的照片**。回到邮局门廊，找到木架上的信封与远山。按 C 举机，先用普通焦段，把两者放进同一张画面。用 A / D 缓慢横移，看山尖能否落进封口，按空格拍照。可再拍一张山峰偏出信封的对照。
3. **选片寄出并读回信**。按 J 打开来信与底片，选择刚拍的照片，通过面板寄出。回信会根据实际构图变化。要证明摄影闭环，留一张取景画面、一张底片或导出的原图，以及回信的截图。
4. **验证续玩**。同一地址、同一档案刷新，点「接着上一次的路」。重新打开旅行册，确认回信和已拍照片仍可看到。测试下载时，从照片大图点「导出原图」，并确认实际生成文件。
5. **继续走日间邮路（可选）**。用地图导航去风来林地拍指路照，或去东岭按来信提示拍转弯处与抵达处两张。去石巷旧镇开绞盘、拍石拱、过桥，再沿路到禅院辨认阿公的窗并交件。跑和跳各有独立的解锁互动，主线可以徒步走。根据实际 HUD、来信和场景反馈操作。
6. **查夜间内容（专项）**。等游戏时间正常入夜，沿地图进花街查看实际开放的摊位、鱼灯和住宿入口。烟花路线先在禅院交件领奖，再按场内提示领火把、出镇找开阔地布置燃放。夜市和烟花分别记录，当前版本以界面实际看到的内容为准。

## 需要本地工程的情况

单次试玩和呈现问题，通过浏览器即可完成。要复跑工程的 QA 脚本、读取 ForgeAX 的结构化观察、调整场景或代码、验证修改前后差异，才需要本地工程、可用的项目依赖和 ForgeAX CLI。请从游戏根目录运行，那里有 `forge.json`、`assets/` 和 `scripts/qa/`。项目当前使用 Node 22.13 或更新版本、pnpm 12.15.0 和 ForgeAX Engine 0.5.0。

```sh
pnpm exec forgeax project check --json
pnpm exec forgeax dev status --json
pnpm exec forgeax dev start --backend auto --json
pnpm exec forgeax project play scripts/qa/opening-envelope.mjs --json
AFTERNOON_QA_ROUTE=walk-only pnpm exec forgeax project play scripts/qa/afternoon-post.mjs --json
```

- 开发预览从 `dev status` 报出的地址进入。上面的 `dev start` 只在没有可复用的预览时运行。
- `opening-envelope.mjs` 用项目的 owner 浏览器复跑信封构图、选择回信、刷新和导出。`afternoon-post.mjs` 提供先跑、先跳和徒步三条路线，上面的命令只复跑徒步。复跑前先确认所用源码和脚本版本相符，先运行一条对本次问题有用的路线。
- 结构化读数可以用来定位问题。要给出「玩家正常玩通」的结论，操作仍须由真实键鼠和游戏界面完成。改存档、传送、加道具或直接发内部动作，只能作为诊断证据。

## 回传结果

在报告里写明试玩 URL 或本地候选、浏览器、视口、新档或续档、实际复跑的路线、到达场景和可见结果。问题还要写明所在地点、日内时刻、天气、相机状态、动作顺序与实际画面。附第一张可玩画面以及问题前后的截图或短录屏。若启动失败，保存页面的 Diagnostics，并写清失败发生在打开网页、出现菜单、开局还是首个键鼠动作。
