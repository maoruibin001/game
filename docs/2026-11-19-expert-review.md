# 《山野来信》产品复核清单

桌面候选构建 `d095b43`，ForgeAX Engine 0.5.0，Zaohua SDK 0.2.0。正常键鼠可从新档实拍、回信、寄出明信片，刷新后继续并重读。以下问题供下一轮专家复核。P1 影响开始游玩或理解主线，P2 影响可读性、手感或使用范围。

| 优先级 | 问题 | 复现步骤与实测观察 | 复核目标 |
| --- | --- | --- | --- |
| P1 | 首次等待接近半分钟 | Chrome 打开本机试玩，计时到开始或继续按钮可操作。M2 Pro 上同构建三次冷缓存为 28.65、28.59、28.98 秒，三次暖缓存为 30.74、30.42、29.10 秒。面板显示「构建场景」约 14.5–16.8 秒，随后再次显示「启动 Worker」约 7.0–7.9 秒。 | 判断入口等待能否满足目标设备上的试玩预期。阶段标签提供定位范围，细化到资源解码、编译和世界初始化仍需 Worker 计时。 |
| P1 | 玩家可以直走到寄信，沿途内容未必能留住人 | 新档出发，沿路拍林地单照，转旧镇绞盘、拍照过桥，在旧镇回信并投递。可一路跳过东岭、拾遗和摄影日程。熟路的一次普通输入复验从脚本开始到邮戳约 3 分 15 秒。 | 让两位初见者独立玩。记录首拍、理解第一封信、主动停留、求助、寄信的时点。若两人都忽略某处，先检查那处的线索有没有出现在自然行走视线里。 |
| P2 | 步行和相机的左键含义切换 | 步行用左键拖视角，按 C 举机后继续按左键，左键会触发快门。首次取景现在会提示「右键拖动」，方向键仍可转向。 | 观察初见者是否仍误拍，或是否需要停下来找键位。 |
| P2 | 旧镇缩图里双峰仍比石拱和屋顶弱 | 转绞盘后回到石拱近侧，从桥未落下的状态用「日常」焦段拍石拱、红邮筒和双峰。导出原片缩到 240 像素宽。两峰之间能看到天空，亮色屋顶和大面积拱体更容易先被认出。 | 给专家同时看旧卡和缩图，先询问最先注意到的三件景物，再核对能否直接指认双峰。 |
| P2 | 脚步随区域切换音色 | 从山口草地走到邮局铺路、木廊，再走旧镇石路和落下的桥。实现把旧镇传为石料、其他区域传为土路，路径材质本身不驱动切换。引擎已报告正常配乐和结尾配乐进入播放，快门、风车、落桥与邮戳的实际清晰度待试听。 | 以正常配乐音量分别用耳机和扬声器试听，记录材质差异、动作音效是否能听清、是否容易和背景声混淆。 |
| P2 | 用另一个浏览器或访问地址时无法继续 | 在地址 A 拍照，等「旅程已记好」。用另一个浏览器或同构建的不同端口打开，会显示新档。回到原浏览器和原地址可继续。标题「继续」附近已说明本机保存范围。 | 确定目标试玩场景中是否需要迁移旅程或多设备继续。 |
| P2 | 原片分辨率和比例随窗口变化 | 在 1280×600 窗口拍照并在底片中下载原图，实测 JPEG 是 1280×600。在 1920×1080 窗口实拍，原图是 1920×1080。 | 若明信片之外的原图也面向独立分享，确认输出是否需要固定比例和最低分辨率。 |
