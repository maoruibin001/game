# 山野来信桌面版产品评审

评审覆盖新档从山口邮局出发，经林地、旧镇和两封回信，到寄出第三封明信片。主线结果能在世界里看见，林地照片让风车启动，旧镇照片放下可通行的桥，最后用玩家自己的照片制成明信片。优先请评审关注首拍提示、两条回信路线和旧镇关键构图。它们决定玩家能否理解拍照的用途，能否凭画面和游戏内的线索自己走完这条路。

桌面硬件 WebGPU 主线测试完成了三张实拍、两封回信和最终寄信。刷新后两封回信及邮戳状态仍在，重新导出的 1920×1080 原图与刷新前字节一致。游戏报告正常旅程配乐和结尾配乐均进入播放状态。 [主线实机记录](../artifacts/play/scripts/qa/startup-fix-journey/play.json)

P1 影响开始游玩、理解主线或达成关键构图。P2 影响手感、可读性或成品感，当前主线有可用路径。

## P1 开局行动与摄影目标

| 问题 | 复现步骤和观察 | 评审目标 |
| --- | --- | --- |
| 新手最醒目的动作是候时 | 新档点「背上行囊，出发」，站在出生点不动。中央下方首先提示按 E 坐一会儿，拍第一张所需的 C 和读信的 J 只在左下角。 [开局画面](../artifacts/play/scripts/qa/startup-fix-journey/01-01-opening.png) | 让新玩家先知道为什么拍、怎么举相机和怎么拍。观察初见玩家能否自行完成第一拍。 |
| 一封来信的两条解法不对等 | 按 J 阅读阿禾的信。正文允许林间单照和东岭双照，东岭却有两块大槽位和「0/2」进度。走林地时又可能看到「箭头和风车都在了」，随附的旧卡标题却是「风铃与风车的合影」。 [回信页](../artifacts/play/scripts/qa/route-letter-ridge/08-10-unanswered.png) · [林地取景](../artifacts/play/scripts/qa/startup-fix-journey/03-03-forest-actual-composition.png) | 两条解法都能被快速找到。相机明确说明当前可以完成的是哪条解法，完成任一路线后让玩家知道这一封已答完。 |
| 旧镇通关照里的双峰不够突出 | 到石拱附近，按 E 转动绞盘，回到石拱外，用常用焦段拍红邮筒、石拱和双峰。相机已允许提交时，拱洞中央最抢眼的仍是桥板与后方建筑，双峰在上方露出一小段。 [合格构图](../artifacts/play/scripts/qa/startup-fix-journey/05-05-old-town-actual-composition.png) | 对照参照卡与真实合格照片，让玩家能凭视觉认出山峰和石拱的关系。 |
| 主线可完成得很快，沿途内容的吸引力需要验证 | 沿已知路线从邮局出发，拍林地和旧镇，在旧镇邮筒寄信，略过山脊、摄影日程和拾遗。两次正常输入测试从脚本开始到盖邮戳分别约 3 分 44 秒和 3 分 15 秒。 | 用初见玩家测实际节奏，尤其观察他们是否愿意停下来探索。熟悉路线的耗时只说明主线下限。 |
| 入口恢复后首帧等待仍长 | 普通桌面 Chrome 打开本地预览，继续等待到能点标题菜单。修复后的单次观察在第 24 秒仍处于启动 Worker 阶段，随后进入菜单。 | 从页面打开计到可操作首帧。需要看设备和浏览器分布，决定是否减少首场景所需资源，或改进这段等待的提示。 |

## P2 反馈、手感和画面

| 问题 | 复现步骤和观察 | 评审目标 |
| --- | --- | --- |
| 构图失败缺少具体主体 | 在林地举相机，保留风车，把风铃挪到遮挡物后或取景边缘。当前规则能识别哪一个主体先失败，部分反馈只说「有景物被挡住了」或「景物有些远」。 [提示规则](../assets/journey/photography.ts) | 失败文案先说清是哪一件景物，再给玩家一步可尝试的动作。 |
| 同一个左键在步行和取景时代表不同动作 | 步行时用左键拖动转镜头。按 C 后，取景改为用右键或方向键，左键成为快门。按键说明藏在屏幕底部。 [取景画面](../artifacts/play/scripts/qa/startup-fix-journey/03-03-forest-actual-composition.png) | 评估从步行切入相机时，是否要把右键提示放到取景框附近。用初见玩家观察误拍情况。 |
| 短窗口内摄影工具盖住入镜画面的右缘 | 将窗口调到 1280×600，举相机，展开「镜头与人物」，选择「帮我拍」。右侧工具面板占据约六分之一画幅，而成片保留完整画面。这项来自现有短窗口实机留档。 [短窗口取景](../artifacts/play/scripts/qa/photography-layout-playthrough/04-viewport-1280x600.png) | 允许玩家在快门前检查完整画幅，同时保留常用快门、变焦和定时操作的可达性。 |
| 技术状态露出在标题和结局 | 打开标题菜单，或寄完最后一封后查看明信片页。右下角仍有 Game、Engine 和 FPS。 [结局画面](../artifacts/play/scripts/qa/startup-fix-journey/08-08-postmarked.png) | 确认玩家默认界面是否要保留这个状态。 |
| 邮筒的重读反馈像一条通知 | 寄出后点「再走一会儿」，站在邮筒旁按 E「读山谷的回信」。屏幕上方短暂显示结局文字，重读完整信件和成片需要去旅行册。 | 评估重读时是否应该重现完整信件和照片，以及是否把旅行册入口提示出来。 |

## P2 音效和存档

| 问题 | 复现步骤和观察 | 评审目标 |
| --- | --- | --- |
| 脚步音色按区域切换 | 从山口草地走上邮局铺路和廊下，再比较旧镇的地面。当前代码把整个旧镇归为石料，其余区域使用土路音色，区内材料变化不会驱动脚步音色切换。 [脚步声路由](../assets/entry/frontend.pack.ts) | 耳机试听草、石、木、桥面是否需要更明确的区分。另以实际扬声器检查风车启动、桥落稳、快门与邮戳能否在正常配乐下听清。 |
| 存档只绑定当前浏览器和访问地址 | 在地址 A 拍照，看「旅程已记好」。同一浏览器打开同构建的另一端口，会见到新档。返回 A 能看到原进度。 | 在「接着上一次的路」附近说明保存位置。若要面向换设备或换地址的场景，再决定是否需要搬移旅行册。 |

初见玩家的摄影难度与完整时长，适合用盲玩验证。音色、响度和声景衔接需要用实际耳机或扬声器试听。
